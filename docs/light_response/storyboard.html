总览

④ 所有子项结果汇总成最终 bin —— 一颗芯片的「体检结论」

这一行在流水线的哪里？

它不是孤立的函数调用，而是白帧测试（Bright Test）流水线上的一站。一次 Bright Test 会依次跑十几个子项，这里只有第一项。

  1. RAW 白帧：点亮均匀光源，采一帧 3840×2160 的 Bayer 原始图。
  2. Split_Channel：拆成 R / Gr / Gb / B 四个 1920×1080 平面。
  3. Light_Response：中心 ROI 四个通道的平均亮度（DN）与 Spec 比较。
  4. Calculate_The_Final_Bin：汇总所有子项，取最严重的失败项作为最终 bin。
// BrightTest::TestFunc_Normal_Bright_ALL()  BrightTest.cpp
      std::vector<Subitem_Result> items_results;
      items_results.push_back(Algorithm_all[site_].Light_Response(test_manage));
      // ... 还有十几个子项 ...
      Subitem_Result bright_result =
          Algorithm_all[site_].Calculate_The_Final_Bin(items_results);
      int code = bright_result.bin;      // 返回给机台分选

所以这一行的返回值只是「一项体检结论」，不是最终分选结果。

分通道

拆完后每个平面是 W/2 × H/2：3840×2160 → 4 × 1920×1080

为什么要先分通道？

传感器输出的是 Bayer 原始图：每个像素前面只盖了一种颜色的滤光片，RG / GB 两个绿点位置不同（Gr、Gb）。

// TestItem::split_channel()  testitems.cpp:57
      for (int i=0; i<h; i+=2)
        for (int j=0; j<w; j+=2) {
          *pb1++ = raw[w*i + j];       // R
          *pb2++ = raw[w*i + j+1];     // Gr
        }
      // 奇数行同理 → Gb / B

拆完后每个平面是 W/2 × H/2。之后所有 ROI、均值都在这个半尺寸平面上算。

关键坐标概念：配置文件里 ROI_X=768 是在 1920 宽的平面上量的，不是 3840 的 RAW。bayer 配错（RG/GB）会导致 R 和 B 互换，值就会整体错位。

算均值

四个均值就是这一子项的「测量值」

DN 是什么？

DN（Digital Number）就是像素的灰度量化值。本例是 8 bit，范围 0~255；10/12 bit 则是 0~1023 / 0~4095。

// 四个通道各开一个线程，互不等待
      MultiThread::get_roi_channel_mean
          -> GetROIMean(data, w, h, x, y, w, h);

      mean = Σ DN / N

均值代表整体响应灵敏度：偏暗说明光电转换弱 / 曝光不足，偏亮说明增益过大或接近饱和。

均值会「稀释」个别坏点：一个 255 的亮点平均到几十万像素里几乎看不出来。所以坏点由 Pixel_Defect、DAG 等子项负责 —— 每个子项各管一件事。

判 Spec

判定：PASS → bin 保持初值 1，grade 0

判定树（代码里的分支顺序）

if (mean_r > max_r || mean_r < min_r ||
          ... 四个通道任一越界 ...) {
          res.is_passed = false;

          if (error_min_open && (... < error_min))
              { bin = 161; grade = 9; }       // 死黑 / 不响应
          else if (error_max_open && (... > error_max))
              { bin = 162; grade = 9; }       // 饱和 / 过曝
          else
              { bin = bin_response;           // 配置值，本例 2201
                grade = grade_response; }     // 本例 9
      }

本例配置：R/B 的 80~220，Gr/Gb 的 144~216，error_MIN=50、error_MAX=241、bin_response=2201。

先判 161 再判 162：即使某个通道同时满足「低于 50」和「另一通道高于 241」，也只会落 161。这是代码顺序决定的，不是巧合。

归档汇总

Calculate_The_Final_Bin 取 grade 最大的失败项 → BrightTest 返回它的 bin

最后，bin 是怎么定下来的？

Subitem_Result final_result("The initial value", true, 1, 0, true);
      for (item : items_results) {
          if (item.g_msg == false) continue;          // 未开启 → 跳过
          if (!item.is_passed &&
              item.grade > final_result.grade)        // 只挑更严重的
              final_result = item;
      }
      return bright_result.bin;                       // BrightTest.cpp:79
  • 全通过 → 返回初值 bin=1, grade=0（良品）。
  • 有失败 → 取 grade 最大的那一项的 bin；同级取先出现的。
  • g_msg=false（未开启 / 版本不匹配）的子项不参与竞争。

Light_Response 在 response_open_mode≠1 或版本号不是 LightResponse_V1.0 时返回 g_msg=false：不是「通过」，而是「不表态」。现场查「为什么这项没卡住」先看这里。
