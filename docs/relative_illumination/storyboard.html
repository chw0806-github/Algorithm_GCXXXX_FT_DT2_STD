定位

③ 它直接用 RAW 全图 + 5 个窗口，不拆通道

它和 Light_Response 有什么不同？

同一个白帧，两项各看一件事：

  • Light_Response：拆通道 → 每个通道一个中心 ROI → 看绝对亮度够不够（80~220 DN）。
  • Relative_Illumination：不拆通道，直接读 RAW → 四角 + 中心 5 个窗口 → 看边缘比中心暗多少（20%~100%）。
// AlgorithmItems::Relative_Illumination_V1_0  algorithmitems.cpp:1320
      double RelIllum = AlgorithmFuncs::TestRelativeIlumination(
              g_buf_raw_, w, h, w_win, h_win);
      if (RelIllum > limit_max_ratio_ || RelIllum < limit_min_ratio_) {
          res.is_passed = false;
          res.bin   = param.bin_;     // 2202
          res.grade = param.grade_;   // 8
      }

坐标体系不同是最大的坑：这里窗口坐标是 RAW 像素；Light_Response 的 ROI 是 拆分后平面的坐标（一半）。

取窗口

5 个窗口全部落在 RAW 上（本图窗口为放大示意）

5 个窗口的位置

窗口大小来自参数 w_win=96、h_win=54；位置在代码里写死：

// TestRelativeIlumination()  cpalgorithmraw.cpp:1576
      ROI_3 = 左上角 [0 .. h_win) × [0 .. w_win)
      ROI_4 = 左下角 [h-h_win .. h) × [0 .. w_win)
      ROI_5 = 右上角 [0 .. h_win) × [w-w_win .. w)
      ROI_6 = 右下角 [h-h_win .. h) × [w-w_win .. w)
      ROI_2 = 中心   [h/2-h_win/2 .. +h_win) × [w/2-w_win/2 .. +w_win)

4 个角窗口各 96×54 = 5184 个像素，加起来只占全图的约 0.25% —— 算得很快。

窗口必须落在有效成像区内。若 w_win 配得比图还大，或者 RAW 含 OB 区，角上取到的就不是有效像素了。

求均值

② 得到 5 个窗口均值（N 都是 5184）

每个窗口一个均值

for (int i=0; i<h_win; ++i)
        for (int j=0; j<w_win; ++j)
          ROI_3 += pData[w*i + j];
      ROI_3 /= cnt;        // 左上角均值
      // 其余三个角、中心同理

五个窗口面积相同（N 都是 5184），所以均值可以直接横向比较，不需要再归一化。

均值本身不看单点：一个坏点落在窗口里几乎不影响结果。边缘坏点、划伤由 ImageDirt / Pixel_Defect 等子项负责。

STEP 04 / 07

算 ratio

ratio 就是这一子项的测量值（单位 %）

两个公式

double darkest = (ROI_3 + ROI_4 + ROI_5 + ROI_6) / 4;
      if (ROI_2 < darkest/10)      return 1000;
      else if (ROI_2 > darkest*10) return 10;
      else return 100 * darkest / ROI_2;
  • darkest：四角均值再平均 → 代表"边缘有多亮"。
  • center：中心窗口均值 → 代表"镜头中心照度"。
  • ratio：边缘占中心的百分比。20% 表示边缘只有中心的 1/5。

注意分母是 center：如果中心被遮挡/压暗，ratio 反而会变大，所以代码才加了 >10 倍的防呆。

STEP 05 / 07

防呆

两条极端保护：中心 < darkest/10 → 1000；中心 > darkest×10 → 10

为什么要防呆？

如果中心暗到接近 0，除法会炸（或得到天文数字）；如果中心远亮于边缘，比值会大于 100%，说明不是"暗角"而是别的问题。

if (ROI_2 < 0.001) ROI_2 = 0.001;   // 防除零
      if (ROI_2 < darkest/10) return 1000; // 中心几乎全黑
      else if (ROI_2 > darkest*10) return 10; // 中心远亮于边缘

两个返回值（1000 和 10）都必然超出 20~100 的 Spec，所以"异常"一定会被卡住，不会误判成良品。

看到 ratio 恰好是 1000 或 10，别怀疑测量精度 —— 那是防呆分支被命中了，去查图像本身（中心是否全黑 / 光源是否偏）。

判 Spec

判定：PASS → bin = 1，grade = 0

判据只有一条

if (RelIllum > limit_max_ratio_ ||   // 100
          RelIllum < limit_min_ratio_) {   // 20
          res.is_passed = false;
          res.bin   = 2202;
          res.grade = 8;

本例配置：min_ratio=20、max_ratio=100、bin=2202、grade=8。

ratio 太小 = 暗角太重（镜头/装配/遮光问题）；ratio 大于 100% = 边缘比中心亮，通常是中心被遮挡或参数错。

和 Light_Response 不同，这里没有 161/162 这种"极端 bin"，只有配置里那一个 bin_。

归档

最终 bin 由 grade 最大的失败项决定

两个子项如何共同决定 bin

  • Light_Response 失败 → bin 2201 / grade 9
  • Relative_Illumination 失败 → bin 2202 / grade 8
  • 两个都失败时，Calculate_The_Final_Bin 取 grade 更大的 → 返回 2201
if (!item.is_passed && item.grade > final_result.grade)
          final_result = item;     // 只换更严重的

所以看到机台回 2201，不代表相对照度没问题——它可能也失败了，只是被更严重的项覆盖。排障要看完整 log（g_str_msg_all）。
